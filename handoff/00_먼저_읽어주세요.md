# 분석 브리핑 — DART 보험지주회사 벤치마킹 데이터

첨부된 CSV 를 분석하기 전에 이 문서를 먼저 읽어 주세요. **이 데이터에는 그냥 읽으면
틀리게 되는 함정이 여럿 있습니다.** 아래 규칙을 지켜야 결과가 맞습니다.

---

## 1. 이 데이터가 무엇인가

금융감독원 **DART 전자공시 OpenAPI** 에서 2026-08-31 에 수집한 원본 데이터입니다.
목적은 **생명보험사 1 + 손해보험사 1 을 기반으로 보험지주회사(금융지주회사법상 비은행지주)를
신설하는 프로젝트의 벤치마킹**입니다.

대상 17개 법인:

| 구분 | 법인 |
|---|---|
| 지주 5 | 신한지주 · KB금융 · iM금융지주 · 우리금융지주 · 한화생명보험 |
| 보험 자회사 9 | 신한라이프생명보험 · 신한이지손해보험 · KB손해보험 · KB라이프생명보험 · iM라이프생명보험 · 동양생명보험 · ABL생명보험 · 한화손해보험 · 캐롯손해보험 |
| 선행·휴면 법인 3 | 오렌지라이프생명보험 · KB생명보험 · 우리금융지주(구) |

모든 행에 출처가 붙어 있습니다: `rcept_no`(접수번호) · `fetched_at`(조회시각) ·
`status`(응답코드) · `raw_path`(원본 파일 경로). **수치를 인용할 때는 `rcept_no` 를 함께
표기해 주세요.**

## 2. 반드시 지켜야 할 규칙 8가지

### ① IFRS4 와 IFRS17 을 하나의 시계열로 잇지 마세요

보험사 회계기준이 **2023년부터 IFRS4 → IFRS17** 로 바뀌었습니다. 손익 계정 구조가
근본적으로 다릅니다.

- `accounting_std_inferred` 컬럼이 `IFRS4`/`IFRS17` 을 표시합니다
- `comparability_break = Y` 는 그 행의 기간에 합병·회계기준 변경이 걸쳐 있다는 뜻입니다
- **함정**: 2023년 보고서의 *전기 비교수치*는 IFRS17 로 재작성된 값이라, 2022년 보고서의
  *당기* 수치와 다릅니다. 같은 2022년인데 값이 둘입니다
- 비교하려면 IFRS4 구간(~2022)과 IFRS17 구간(2023~)을 **나눠서** 제시하세요

### ② 금액 단위가 연도마다 다를 수 있습니다 — 절대 임의 환산 금지

같은 컬럼인데 회사가 연도에 따라 단위를 바꿔 적은 사례가 실제로 있습니다.

> 한화생명 `frst_acqs_amount`: 어떤 해는 `449,900,000,000`(원), 어떤 해는 `449,900`(백만원)

- `amount_raw` 가 **원문 그대로**입니다. `amount` 는 부호·쉼표만 처리한 값입니다
- 원문 표 데이터는 `unit_hint` 컬럼에 `(단위 : 백만원)` 같은 표기가 그대로 들어 있습니다
- **단위가 확인되지 않으면 환산하지 말고 "단위 확인 필요"로 표시하세요**

### ③ 빈칸의 의미가 여러 가지입니다 — 0 으로 채우지 마세요

`parse_status` 컬럼이 구분해 줍니다:

| 값 | 의미 |
|---|---|
| `ok` | 정상 파싱 |
| `key_absent` | DART 응답에 그 항목 자체가 없음 |
| `empty_string` | 빈 문자열 |
| `dash` | 회사가 `-` 로 표기 (해당 없음) |
| `unparseable` | 숫자로 해석 불가 |

**어떤 경우에도 0 으로 대체하지 마세요.** 없는 건 없는 겁니다.

### ④ `99_미확보목록.csv` 의 공백은 대부분 오류가 아닙니다

`reason_code` 를 보세요:

- `api_013` (413건) — DART 가 "해당 공시 없음"으로 정상 응답. **오류 아님**
- `not_applicable_entity_window` (252건) — 법인 생존기간 밖. 예: 캐롯손해보험은
  2025-10-01 한화손보에 흡수합병돼 소멸했으므로 그 이후 데이터는 *존재하지 않는 것*이
  정상입니다. 누락이 아닙니다
- `api_000_empty_list` (17건) — 정상 응답인데 목록이 빔

### ⑤ 계정과목 매핑은 되어 있지 않습니다 — 임의로 판단하지 마세요

보험손익·투자손익에 해당하는 계정 이름이 **회사마다 다릅니다.** 의도적으로 매핑하지
않았습니다.

- `00_계정과목목록.csv` 에 회사별 `account_nm` 고유값 21,700건이 전부 들어 있습니다
- `account_id` 는 IFRS17 확장계정에서 `-표준계정코드 미사용-` 인 경우가 흔해
  **단독 키로 쓰면 안 됩니다**
- 특정 지표를 만들어야 하면, 어떤 계정을 썼는지 **명시적으로 밝히고** 진행하세요

### ⑥ 회사명 부분일치로 조인하지 마세요

실제 사고 사례:

> `12_지분관계.csv` 에서 "한화손해보험"으로 부분일치하면 FY2022 이후 **지분율 100%** 가
> 잡힙니다. 그런데 이건 보통주가 아니라 `한화손해보험(유상증자)_전환우선주` 라는
> **별개 종목**입니다. 보통주 지분율은 51.36% 로 매년 동일합니다.

- `child_match_method` 컬럼이 조인 방식을 표시합니다 (`target_name_exact` / `unmatched`)
- 회사명에 앞뒤 공백이 붙은 경우도 있습니다 (`' 한화손해보험 '`)

### ⑦ 원문 표는 격자로 정리되어 있지 않습니다

`원문_계열구조.csv`, `원문_CSM롤포워드.csv` 는 표를 **셀 단위**로 담고 있습니다.
`rowspan` / `colspan` 이 원문 그대로 들어 있고, 격자로 펼치지 않았습니다.

이유: CSM 롤포워드 표 같은 경우 헤더에 `colspan=9`, `rowspan=3` 이 섞여 있어 격자를
잘못 추론하면 **기말 CSM 이 전기 칸으로 밀립니다.** 표를 재구성할 때 `row_index` ·
`cell_ord` · `rowspan` · `colspan` 을 함께 보고 직접 정렬해 주세요.

### ⑧ 정형 API 는 2015년부터입니다 — 출범 데이터는 원문에만 있습니다

DART 정기보고서 주요정보 API 의 데이터 제공 시작이 **2015년**입니다(실측 확인).
따라서:

| 지주 | 설립 | 출범 시점 정형 데이터 |
|---|---|---|
| 신한지주 | 2001-09-01 | **없음** → 원문만 |
| KB금융 | 2008-09-29 | **없음** → 원문만 |
| iM금융지주 | 2011-05-17 | **없음** → 원문만 |
| 우리금융지주(구) | 2001-03-27 (2014 해산) | **전무** → 원문만 |
| 우리금융지주(신) | 2019-01-11 | 있음 |

출범 시점 계열사 구조는 `원문_계열구조.csv` 의 **첫 사업보고서** 행에서 찾아야 합니다.
예: 신한지주는 `rcept_no = 20020327000215`.

**주의**: 2000년대 초 보고서는 용어가 다릅니다. 「계열회사」라는 말이 아예 안 나오고
「관계회사」·「자회사」·「기업집단」을 씁니다.
