# 조직 팩 초안 생성 지시문 (Claude Code용 — 부서 이동 절차 1단계)

이 문서는 덱보드 아티팩트가 아니라 **Claude Code 대화에서** 쓰는 지시문 정본이다 (build-artifact PROMPTS 미포함).
새 부서 벤치마크 덱을 확보하면 아래를 그대로 실행한다.

## 입력 준비

```bash
npm run pack:probe -- <새부서덱1.pptx> <새부서덱2.pptx> ...   # 판형·색·폰트·종결·기호 통계
npm run deck:text  -- <새부서덱1.pptx> /dev/null              # 전문 텍스트 (문체 판독용)
```

## Claude Code에 줄 요청문

> `<덱들>.probe.json`과 텍스트 추출 결과를 근거로 `rules/org/_template/` 4파일 형식에 맞춰
> `rules/org/<새팩>/` 초안(style.json·colors.json·visual.json·exceptions.json)을 만들어줘.
> 룰북 §5(문체)·§6(역할색·시각)도 같은 내용으로 개정 초안을 써줘. 아래 판정 원칙을 따를 것.

## 판정 원칙 (초안 작성 규칙)

1. **통계는 후보, 확정은 대화** — 프로브 수치는 신호일 뿐이다. 종결어미·금칙·역할 매핑처럼 해석이 필요한 항목은
   근거(빈도·출현 문맥)를 붙여 제안하고, 확신이 없는 항목은 초안에 `_확인필요` 주석을 남긴다. 스크립트가 4파일을
   자동 생성하지 않는 이유가 이것이다.
2. **역할 매핑 방법** — 채움색 최빈값에서 구조색(제목·밴드)·본문색·배경색을 추리고, 글자색에서 잉크·뮤트를 추린다.
   당사/문제/강조 계열은 **출현 문맥**(✕·○ 근처, 형광, 강조 박스)으로 판정한다. hex는 colors.json에만 —
   역할 키 세트는 `_template/colors.json`과 동일해야 엔진이 돈다 (누락 키는 showcase 재빌드가 즉시 잡음).
3. **종결어미** — last2 통계에서 라벨(명사 종결)과 서술(어미 종결)을 구분해 서술 쪽만 endings 후보로.
   개조식(함/됨/임)이 아닌 관행(예: "~습니다", 명사형 종결)이 지배적이면 그대로 반영한다 — 팩은 조직을 따른다.
4. **기호** — 프로브 symbols에서 실제로 쓰인 것을 allow로, 안 쓰인 현행 금지 기호(—·행두 "- ")는 상태 유지.
   **△가 마이너스 표기로 쓰이는지**는 텍스트 문맥으로 반드시 확인 (경영관리 관행에서 흔함 — minusRule 개정 대상).
5. **판형** — probe canvas가 세로(portrait)면 팩 생성은 진행하되, 엔진은 현재 wide만 지원함을 사용자에게 알리고
   판형 확장(BACKLOG)을 먼저 논의한다.
6. **영문 라벨 후보** — englishLabelCandidates 중 고유명사(사명·시스템명)는 exceptions.json으로,
   섹션 라벨(AGENDA류)은 forbidden.englishLabels로 나눈다.

## PDF·인쇄본만 있을 때 (프로브 불가 대체 절차)

- 판형·색: PDF 뷰어 스포이드로 주요 색 hex를 수동 채집 (제목·밴드·강조·본문 각 1개 이상)
- 문체: 텍스트를 복사해 붙여넣으면 종결·기호는 동일하게 판정 가능
- 이 경우 colors.json 초안에 `_확인필요` 주석을 남기고, 첫 실물 pptx 확보 시 프로브로 재검증

## 이후 절차 (README '부서 이동 절차' 2~5단계)

active.json 전환 → 룰북 §5·§6 교체 → `npm run artifact:build` → 골든·showcase 재빌드.
**showcase 빌드 성공 = 새 팩 role 키 완전성 증명** (미정의 role은 roleColor가 즉시 던짐).
