# PPT 프레임워크 룰북 v0.2

한국 보험사 내부 보고용 슬라이드를 만들 때 적용하는 규칙 체계.
실전 덱 1건(생보 파일럿 컨셉 보고, 2회 개정)에서 추출된 v0.1을, 컨텍스트 교차 검증(`점검결과.md`)의 픽스를 반영해 개정한 판.

> **기계용 정본과의 관계**: 이 문서는 사람용 정본이다. 도구(덱보드 아티팩트·빌드 엔진)가 소비하는 기계용 정본은 `ppt/rules/*.json`이며, 이 문서의 조항과 rules 키의 대응은 `CHANGELOG.md`의 대응표를 따른다. **개정은 반드시 두 층을 쌍으로 고친다.**

## 1. 파이프라인 (강제 순서)

1. **정의서** — 덱을 열기 전 5문항에 답을 적음
2. **헤드라인 체인** — 장당 메시지 한 문장, 체인만 읽어 논리 성립 확인
3. **구멍 검사** — 체인을 챕터 3 유형학으로 레드팀 (오디언스 프라이어 입력 필수)
4. **폼 스터디** — 장별로 메시지의 관계어를 짚고 표현 형태 후보 2~3개 중 선택
5. **제작** — 챕터 1·2 규정 적용, 검증-렌더-QA 루프
6. **사다리 QA** — L1~L5 순서로 장별 최종 점검

**강제의 운영 정의** (v0.2 신설): "순서 강제"는 단계 건너뛰기 금지를 뜻하며 상위 단계의 수정 금지를 뜻하지 않는다. 상위 단계(정의서·체인)를 수정하면 하위 산출물(구멍 검사 결과·폼 확정)은 자동으로 "재검토 필요" 상태가 된다. 도구는 순서 위반을 차단 대신 경고로 구현할 수 있다. 체인 확정 전 제작 착수는 금지.

## 2. 정의서 5문항

- Q1. 이 자리가 끝났을 때 방이 무엇을 하기를 원하는가 (승인 / 방향 확인 / 이견 해소 / 인지) — 답이 §3 결정표를 통해 아키타입을 결정
- Q2. 그렇게 하려면 그들이 무엇을 믿어야 하는가 — 한 문장, governing thought
- Q3. 지금 그들이 그걸 믿지 않는 이유는 무엇인가 — **본론 구간의 배열은 분석 순서가 아니라 저항 순서를 따름** (골격과의 관계는 §3 우선순위 조항)
- Q4. 각 저항을 무너뜨리는 가장 강한 근거 하나는 — 저항 하나당 근거 하나, 쌓지 말고 고름
- Q5. 이번에 다루지 않을 것은 무엇인가

Q3 보강(오디언스 프라이어): ⓐ 이 방이 최근 본 관련 보고·장표는? ⓑ 이 방의 평가 기준·KPI는? ⓒ 이 안이 통과되면 누가 무엇을 잃는가?

**Q1 선택 기준** (v0.2 신설, 드라이런 A1 해소): '승인'은 자원 배분(예산·인력·일정)의 결정을 요구하는 자리, '방향 확인'은 자원 결정 없이 진행 방향의 동의만 구하는 자리. 둘이 겹치면 이번 자리에서 결재가 나야 하는가로 판정.

## 3. 아키타입 5종 [가설] + 결정표

골격:

- 의사결정 요청형: 요청사항 → 왜 지금 → 대안·평가 기준 → 권고·근거 → 리스크 → 다음 단계
- 개념 제안형: 현 구조의 한계 → 왜 지금 → 개념 한 장 → 작동 메커니즘 → 왜 이 시작점 → 미결 사항
- 분석 결과형: 답 → 질문·접근 → 발견 → 시사점 → 한계·다음 검증
- 현황 보고형: 요약 → 지표 → 이슈·대응 → 결정 필요 사항
- 정보 전달형: 맥락 → 축 셋 → 축별 핵심 → 시사점

**결정표 (Q1 답 → 아키타입)** (v0.2 신설, F1):

| Q1 답 | 기본 아키타입 | 분기 조건 |
|---|---|---|
| 승인 | 의사결정 요청형 | — |
| 방향 확인 | 개념 제안형 | 안건에 미검증 신규 개념이 포함되면 개념 제안형, 기존 안건의 검증 결과가 중심이면 분석 결과형 |
| 이견 해소 | 분석 결과형 | 이견의 근원이 사실 판단이면 분석 결과형, 개념 이해 차이면 개념 제안형 |
| 인지 | 현황 보고형 | 결정 필요 사항이 있으면 현황 보고형, 없으면 정보 전달형 |

타이브레이커: 분기 조건으로도 갈리지 않으면 **덱의 마지막 장이 무엇이어야 하는가**로 판정 — 다음 단계(의사결정), 미결 사항(개념), 다음 검증(분석), 결정 필요 사항(현황), 시사점(정보).

**구조 결정 우선순위** (v0.2 신설, F2): 아키타입 골격은 **장의 종류와 뼈대**(도입·마무리 포함)를 결정하고, Q3의 저항 순서는 **본론 구간 내부의 배열**을 결정한다. 충돌 시 본론 구간 내에서는 저항 순서가 우선하며, 골격의 도입부(예: 현 구조의 한계·왜 지금)와 마무리부(예: 미결 사항)는 고정한다. 골격 칸 수가 체인 줄 수 제한을 넘으면 본론 칸을 병합하되 도입·마무리는 유지한다.

## 4. 판단 사다리 (QA, 위에서 아래 순서 강제)

- **L1 존재** — 이 장은 체인에서 어떤 저항을 맡는가. 답 없으면 삭제
- **L2 메시지** — 헤드메시지가 주장인가 라벨인가 ("그래서?"에 답하는가). 장당 메시지 하나
- **L3 증거** — 본문이 헤드메시지를 증명하는가. 증명하지 않는 요소는 부록행
- **L4 시선** — 3초 안에 어디부터 볼지 아는가 (스퀸트 테스트)
- **L5 잉크** — 빼도 메시지가 안 바뀌는 요소는 제거

메타 규칙: 아랫단은 윗단을 구하지 못함. "못생긴" 슬라이드의 8할은 L2 문제.

**화해 조항 (L5 × 챕터 2 밀도)** (v0.2 보강, F5): L5는 정보 없는 잉크를 빼라는 것이지 정보를 빼라는 것이 아님. 빈 프레임은 깔끔이 아니라 미완성으로 읽힘. 채울 정보가 없으면 잉크가 아니라 프레임을 줄일 것. 추가 규정:

1. **가정 수치의 지위**: 챕터 2가 강제한 가정 수치("(예시)" 표기 + 각주 근거)는 '정보 있는 잉크'로 간주하며 L5의 제거 대상이 아니다.
2. **구조적 프레임**: 프레임이 폼의 구조적 구성 요소(비교 2열의 한쪽 열 등)인 경우 프레임 축소보다 최소 정보(조건 줄·각주)로 채우는 것을 우선한다.
3. **반복 예외의 판정**: 반복이 곧 메시지인 경우(예: 변하지 않음을 보여주는 동일 라벨 반복) 잉크 규칙보다 의도가 우선하되, 그 반복이 헤드메시지의 직접 증거인 경우에만 해당한다 (헤드메시지와 무관한 반복은 잉크).

## 5. 챕터 1 — 문체 규정 [조직 팩]

**2단 제목 체계**
- 상단(크게): 주제 라벨 — 기능명·주제 명사 (예: "1. 무사고 전환 (리밸런싱)"). 시나리오·장면 헤더 금지 (예: "건강이 좋아졌을 때" ✕)
- 하단: 헤드메시지 1~2개 단문, 각 35자 안팎 (**허용 폭 ±5자**, v0.2 확정 — F11). 주장은 여기 삶. 체인 테스트는 이 층에서 수행하며, 헤드메시지가 2문장이면 둘 다 읽는다
- 헤드메시지가 라벨의 반복이면 실패 (정보가 있어야 함)

**개조식·사실체**
- 종결: ~함 / ~됨 / ~임
- 수치가 있으면 문장보다 수치 우선
- 가치판단문은 근거문으로 전환하고 사실과 기대를 분리
- 출처 없는 통계 **및 타사 사실 주장** 금지 (v0.2 확장 — F15). 미확보 시 "출처 확인 필요" 명기 또는 삭제

**금칙**
- 대구·리듬 슬로건 ("~할수록 ~해지는") ✕
- 은유 ("엔진", "문이 닫히지 않는다") ✕ → 기능·절차 서술로. **경계**: §8 관계어(구동·공급 등)는 관계 유형을 지시하는 분류 어휘로서 허용되며, 헤드메시지·본문 텍스트에 사물 은유로 쓰는 것이 금지 대상
- 고객 대사·상황 인용을 말풍선에 싣는 것 ✕ → 상황×결과 표로. **사실 주석의 말풍선 콜아웃은 챕터 2 주석 레이어 규정에 따라 허용** (v0.2 명확화 — F12: 금지 대상은 내용이지 도형이 아님)
- 영문 섹션 라벨 (EXECUTIVE SUMMARY, EXHIBIT, SO WHAT) ✕ → 요약, 도표 N, 시사점. 단 고유명사(이니셔티브명)는 예외 — 예외 목록은 `rules/org/<팩>/exceptions.json`에 등재
- 과장 수식어 ("신개념", "혁신적") ✕

**문장부호** (v0.2 확장 — F3·V7: 실물 기준 성문화)
- 연결: 콤마 / 부연: 괄호 / 정의·나열 도입: 콜론 / 동급 나열: 가운뎃점(·)
- 허용 기호: 범위 물결(~), 화살표(→), 더하기(+), ✕/○ 스탬프, **각주 접두(*), 제목·러닝헤더 구분자(|), 원문자(➊➋➌·①②③ — 기능 넘버링·나열 도입용)**
- 금지: 대시(—), 하이픈 접두(- )
- 마이너스 기호 대신 "인하/감소" 서술 (△ 기호는 감소로 오독될 수 있어 변화량 표기에 사용 금지)

**서사의 지위**: 서사·감성은 삭제가 아니라 강등 — 텍스트 층에서 빼고 본문 비주얼(여정 도표)과 구두 발표(발표자 노트)로 내림.

## 6. 챕터 2 — 시각 규정 [조직 팩, 벤치마크 1개 출처 주의]

- **컨벤션은 반복, 폼은 변주**: 색 의미·스탬프·제목 밴드는 전 장 동일하게, 레이아웃 폼은 연속 2장 이상 동일 금지. **폼 동일의 1차 판정 기준**: 본문 영역의 템플릿 id가 같으면 동일 (v0.2 — F11)
- **빈 프레임 금지**: 모든 프레임은 차트·표·조건 줄·각주 중 하나 이상으로 채움 (화해 조항 참조)
- **주장마다 숫자**: 수치가 없으면 가정 수치 + "(예시)" 주석. 예시 가정은 각주에 근거 명기 (예: "* 등급당 5~6% 가정"). **도구·AI가 생성한 수치에도 (예시) 표기가 자동 전파되어야 한다** (v0.2 — F8)
- **역할색** (v0.2 확장 — V3: 실물 기준 재작성): 색은 장식이 아니라 지목. 기본 배정 —
  - 네이비 = 구조 (제목·밴드·스트립)
  - 파랑 = 당사·긍정
  - 빨강 = 기존의 문제·✕ (당사 측 강조에 사용 금지)
  - 회색 = 기존·중립
  - 형광노랑 = 헤드 키워드
  - **기능 구분색 1(시안)·기능 구분색 2(라벤더)** = 상품 기능·트랙 구분 전용. 동일 색은 전 장에서 동일 대상만 지목한다
  - 구체 hex 값은 `rules/org/<팩>/colors.json`이 정본
- **강조는 장당 하나의 유채색 원칙**: 역할색에 따른 지목(기능 구분 등)은 강조로 세지 않으며, 헤드 키워드 형광·강조 박스류가 이 원칙의 대상
- **형광 시스템**: 헤드메시지 핵심 구절 형광은 전 장 시스템으로 적용하거나 전무. 단발 사용 금지. **"전 장"은 표지·목차·부록을 제외한 본문 장** (v0.2 — F11)
- **주석 레이어**: 말풍선 콜아웃·점선 강조 박스는 차트 위 핵심 **1곳에만** — 콜아웃과 강조 박스의 동시 사용도 금지 (v0.2 명확화 — V2)
- **차트 규정**: 축·단위 명기, 범례보다 직접 라벨 우선 (계열 3개 이상 반복 등장 시 범례 허용), 격자선 최소화. **차트·밴드 제목은 대상·조건을 서술하고 결론은 헤드메시지가 선점한다 — 결론 중복 금지** (v0.2 개정 — F14: 실물 관행 기준으로 확정)

## 7. 챕터 3 — 구멍 유형학 [초안]

체인 확정 후, 제작 전 실행하는 레드팀 검사. 6유형:

1. **프레임 충돌** — 방이 가진 기존 프레임·이전 장표가 내 주장을 기각함. 테스트: "이 방이 본 프레임 중 이 주장을 기각하는 것은?" 보수: 프레임을 부정하지 말고 확장
2. **암묵 전제** — 체인이 말하지 않은 가정 위에 서 있음. 테스트: "이 링크가 참이려면 무엇이 참이어야 하고, 그건 어디서 증명되나?"
3. **비약** — 헤드 N→N+1 사이 추론 한 칸을 독자가 메워야 함
4. **무방비 절대어** — "유일한·최초·모두" 등 반례 하나에 무너지는 주장. 보수: 한정어 또는 반례 선제 처리
5. **내부 충돌** — 한 장의 주장이 다른 장의 주장·증거를 약화시킴
6. **이해관계 미처리** — 논리는 성립하나 방 안의 누군가가 잃는 것을 다루지 않음

②~⑤는 체인 텍스트만으로 검출 가능. ①·⑥은 오디언스 프라이어(정의서 Q3 보강 3문항)를 입력한 만큼만 검출됨 — 검사 도구는 프라이어를 끌어내는 질문을 강제해야 함.

**적용 단위·종료 조건** (v0.2 신설 — F13): 6유형 각각의 테스트 질문을 체인의 전 링크(N→N+1)와 전 장에 1회 이상 적용하고, 한 바퀴에서 신규 검출이 0이면 종료한다.

검출 항목의 처분: (a) 덱에 반영 / (b) 구두 대응으로 결정하고 **예상 문답 메모 기록** / (c) 기각(**사유 기록**). 셋 중 하나로 반드시 처분하며, 메모·사유는 검사 기록에 남긴다.

- **덱 스펙(deck-spec JSON)이 제작의 유일한 입력** — 스펙에는 색 hex를 직접 쓰지 않고 역할(role)만 쓴다 (v0.2 신설, 조직 팩 교체 가능성 보장)

- 기존 파일 수정은 python-pptx로 텍스트 교체(서식 보존), 구조 변경 시 리빌드
- 수치 미확보 시 "(예시)" 주석 의무, 각주에 가정 명기. AI·도구 생성 수치는 assumed 플래그로 전파 (F8)

## 10. 용어 (v0.2 보강 — F11)

- **체인**: 전 장의 헤드메시지를 순서대로 이은 것. 체인만 읽어 보고가 성립해야 함 (고스트 덱 테스트)
- **전 장**: 표지·목차·부록을 제외한 본문 장 (체인·형광 시스템·컨벤션 판정의 범위)
- **폼 동일**: 본문 영역의 템플릿 id가 같은 경우 (1차 기준). 템플릿이 달라도 본문 골격 배치가 사실상 같으면 육안 QA에서 동일로 판정할 수 있음
- **덩어리**: 정의서 Q4의 단위 — 저항 하나 (Q3에서 식별된 저항 목록의 항목)
- **오디언스 프라이어**: 보고받는 방이 이미 가진 프레임·기준·이전 보고
- **폼 스터디**: 한 장의 메시지를 서로 다른 표현 형태 후보로 스케치해 비교·선택하는 단계
- **컨벤션/폼**: 컨벤션=색 의미·스탬프·밴드 등 의미 체계(반복 대상), 폼=레이아웃 구조(변주 대상)
- **조직 팩**: 부서·조직 이동 시 교체되는 규칙 묶음 (`rules/org/<팩>/` — 문체·역할색·시각 파라미터·예외 목록). 방법론(아키타입·구멍 유형학·관계어·사다리)은 `rules/core/`로 조직 불변
