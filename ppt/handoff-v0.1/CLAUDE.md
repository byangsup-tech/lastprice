# CLAUDE.md — PPT 프레임워크 (초안)

이 저장소에서 슬라이드·덱 관련 작업을 할 때 아래 규칙을 자동 적용한다.
전체 규정은 rulebook/룰북_v0.1.md, 이 문서는 실행 요약이다.

## 파이프라인 (순서 강제)
정의서 → 헤드라인 체인 → 구멍 검사 → 폼 스터디 → 제작 → 사다리 QA.
체인이 확정되지 않은 상태에서 슬라이드 제작을 시작하지 않는다.
사용자가 "덱을 만들자"고 하면 먼저 정의서 5문항(룰북 §2)의 답을 확인하거나 질문한다.

## 문체 (챕터 1 요약)
- 장 제목: 기능명·주제 명사를 크게. 시나리오 헤더 금지
- 헤드메시지: 개조식(~함/됨/임) 단문 1~2개, 각 35자 안팎, 주장 포함
- 금칙: 대구 슬로건, 은유, 고객 대사, 영문 섹션 라벨, 과장 수식어
- 문장부호: 콤마·괄호·콜론·가운뎃점만. 대시(—)와 하이픈 접두(- ) 금지. 마이너스는 "인하/감소"로 서술
- 출처 없는 통계 금지. 가정 수치는 "(예시)" + 각주 근거

## 시각 (챕터 2 요약)
- 컨벤션(색 의미·스탬프·밴드)은 전 장 반복, 폼(레이아웃)은 연속 2장 동일 금지
- 빈 프레임 금지: 프레임마다 차트·표·조건 줄·각주 중 하나 이상
- 역할색: 파랑=당사·긍정, 빨강=기존 문제·✕, 회색=기존·중립, 형광=헤드 키워드(전 장 시스템으로만)
- 차트: 축·단위 명기, 직접 라벨, 제목이 결론 선점

## 제작
- pptxgenjs, LAYOUT_WIDE, 맑은 고딕 전 요소 지정
- 빌드 후 반드시: 파일 검증 → PDF 렌더 → 전 장 육안 QA → 수정 루프
- 기존 파일 텍스트 수정은 python-pptx(run 단위 교체로 서식 보존)
- 완성 기준: 검증 통과 + 렌더에서 텍스트 충돌·가림·잘림 0건 + 사다리 L1~L5 통과

## 금지
- 실명(동료·협업자) 기록 금지
- 통계·수치 창작 금지 (가정임을 명시하지 않은 수치)
- 체인 없이 장 단위 제작 착수 금지
