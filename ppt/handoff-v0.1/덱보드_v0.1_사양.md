# 덱 보드 v0.1 사양 (구현 전 검토용)

파이프라인 1~4단계(정의서 → 체인 → 구멍 검사 → 폼 스터디)를 하나의 화면에서 운영하는 도구.
형태: claude.ai 아티팩트(React 단일 파일). Anthropic API를 아티팩트 내부에서 직접 호출(키 불요), window.storage로 덱 단위 영속.

## 원칙
- 판단은 대화·사람이, 반복·추적은 도구가 담당. 도구는 정의서·체인을 대신 써주지 않고, 빠진 입력을 질문으로 강제함
- 기존 폼 스터디 도구(code/form-study.jsx)를 내부 루프로 흡수

## 화면 구성 (탭 3 + 내부 루프)

### 탭 1. 정의서
- 5문항 입력 폼 + 프라이어 3문항(방이 본 보고 / 평가 기준 / 누가 잃는가)
- Q1 선택 시 아키타입 자동 제안(수정 가능)
- 미입력 문항이 있으면 탭 2 잠금 해제하되 경고 배지 표시(차단은 하지 않음)

### 탭 2. 체인
- 한 줄 = 한 장. 각 줄: 라벨(주제) + 헤드메시지 + 상태(메시지 확정 / 폼 확정 / 제작 완료)
- 고스트 뷰: 헤드메시지만 연속으로 읽는 체인 테스트 화면
- 단발 AI 진단(선택): "헤드만 읽고 논리가 서는가, 끊기는 링크는 어디인가" 1회 호출
- 줄 순서 드래그 변경, 아키타입 골격 프리셋 삽입

### 탭 3. 구멍 검사
- 입력: 체인 전체 + 정의서 + 프라이어
- 호출: 유형학 6종(룰북 §7) 기준으로 검출 목록 생성. 항목당 {유형, 걸린 체인 위치, 예상 반문(실제 문장), 최소 보수안}
- 프라이어가 비어 있으면 검사 전에 프라이어 질문을 먼저 반환하도록 프롬프트 설계 (①⑥은 프라이어 의존임을 UI에 명시)
- 각 항목 처분 버튼: 반영 / 구두 대응(메모) / 기각(사유) — 처분 완료율 표시

### 내부 루프. 폼 스터디
- 탭 2의 각 줄에서 진입. 기존 form-study 로직 재사용(관계어 분석 → 후보 2~3 스케치 → 선택 → 제작 지시서)
- 선택 결과가 해당 줄 상태를 "폼 확정"으로 갱신

## 저장 스키마 (window.storage)
- deckboard:decks:v1 → [{id, title, createdAt}]
- deckboard:deck:{id} → {definition:{q1..q5, priors[]}, archetype, chain:[{label, head, status, form?}], holes:[{type, at, question, fix, disposition}]}
- formstudy:runs:v1 → 기존 폼 스터디 기록과 공유(승률 사전 축적)

## API 호출 설계
- 모델 claude-sonnet-4-6, JSON 전용 응답 강제, 체인 진단·구멍 검사·폼 스터디 각각 독립 프롬프트
- 실패 시 재시도 1회 + 수동 진행 경로 항상 제공

## 한계 (명시)
- 프레임 충돌·이해관계 구멍은 입력된 프라이어 범위 내에서만 검출
- 체인 품질 판단의 최종 책임은 사람. 도구는 검사·기록·강제 질문까지만

## 점검 요청 사항
1. 이 구성이 파이프라인 1~4단계를 실제로 커버하는가, 빠진 상태·전이가 있는가
2. 저장 스키마의 결함(동시 수정, 버전 충돌, 용량)
3. 구현 순서 제안: 어떤 탭부터 만들어야 검증 가치가 가장 큰가
4. 만들 가치가 없다고 판단되면 그 사유 (대화 운영 대비 도구화의 한계 이득)
