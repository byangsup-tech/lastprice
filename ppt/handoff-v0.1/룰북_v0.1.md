# PPT 프레임워크 룰북 v0.1

한국 보험사 내부 보고용 슬라이드를 만들 때 적용하는 규칙 체계.
실전 덱 1건(생보 파일럿 컨셉 보고, 2회 개정)을 통과하며 추출된 규칙이며, 문서 내 예시는 해당 덱에서 가져옴.

## 0. 문서 상태

| 장 | 상태 | 근거 |
|---|---|---|
| 파이프라인·정의서·사다리 | 확정 | 실전 1건 전 과정 적용 |
| 아키타입 5종 | 가설 | 분류 검증 미실시 (최근 덱 10~15건 분류 테스트 필요) |
| 챕터 1 문체 | 확정 | 조직 피드백 1회 반영 |
| 챕터 2 시각 | 확정(주의) | 벤치마크 1개(대형 생보사 배타적사용권 신청 자료)에서 추출, 과적합 위험 |
| 챕터 3 구멍 유형학 | 초안 | 실전 검출 2건(프레임 충돌 1, 암묵 전제 1) |
| 폼 스터디 사전 | 시드 | 템플릿 9종, 승률 데이터 축적 전 |

## 1. 파이프라인 (강제 순서)

1. **정의서** — 덱을 열기 전 5문항에 답을 적음
2. **헤드라인 체인** — 장당 메시지 한 문장, 체인만 읽어 논리 성립 확인
3. **구멍 검사** — 체인을 챕터 3 유형학으로 레드팀 (오디언스 프라이어 입력 필수)
4. **폼 스터디** — 장별로 메시지의 관계어를 짚고 표현 형태 후보 2~3개 중 선택
5. **제작** — 챕터 1·2 규정 적용, 검증-렌더-QA 루프
6. **사다리 QA** — L1~L5 순서로 장별 최종 점검

순서 역행 금지. 체인 확정 전 제작 착수 금지.

## 2. 정의서 5문항

- Q1. 이 자리가 끝났을 때 방이 무엇을 하기를 원하는가 (승인 / 방향 확인 / 이견 해소 / 인지) — 답이 아키타입을 결정
- Q2. 그렇게 하려면 그들이 무엇을 믿어야 하는가 — 한 문장, governing thought
- Q3. 지금 그들이 그걸 믿지 않는 이유는 무엇인가 — **본론 구조는 분석 순서가 아니라 저항 순서를 따름**
- Q4. 각 저항을 무너뜨리는 가장 강한 근거 하나는 — 덩어리당 하나, 쌓지 말고 고름
- Q5. 이번에 다루지 않을 것은 무엇인가

Q3 보강(오디언스 프라이어): ⓐ 이 방이 최근 본 관련 보고·장표는? ⓑ 이 방의 평가 기준·KPI는? ⓒ 이 안이 통과되면 누가 무엇을 잃는가?

## 3. 아키타입 5종 [가설]

- 의사결정 요청형: 요청사항 → 왜 지금 → 대안·평가 기준 → 권고·근거 → 리스크 → 다음 단계
- 개념 제안형: 현 구조의 한계 → 왜 지금 → 개념 한 장 → 작동 메커니즘 → 왜 이 시작점 → 미결 사항
- 분석 결과형: 답 → 질문·접근 → 발견 → 시사점 → 한계·다음 검증
- 현황 보고형: 요약 → 지표 → 이슈·대응 → 결정 필요 사항
- 정보 전달형: 맥락 → 축 셋 → 축별 핵심 → 시사점

## 4. 판단 사다리 (QA, 위에서 아래 순서 강제)

- **L1 존재** — 이 장은 체인에서 어떤 저항을 맡는가. 답 없으면 삭제
- **L2 메시지** — 헤드메시지가 주장인가 라벨인가 ("그래서?"에 답하는가). 장당 메시지 하나
- **L3 증거** — 본문이 헤드메시지를 증명하는가. 증명하지 않는 요소는 부록행
- **L4 시선** — 3초 안에 어디부터 볼지 아는가 (스퀸트 테스트)
- **L5 잉크** — 빼도 메시지가 안 바뀌는 요소는 제거

메타 규칙: 아랫단은 윗단을 구하지 못함. "못생긴" 슬라이드의 8할은 L2 문제.

**화해 조항 (L5 × 챕터 2 밀도)**: L5는 정보 없는 잉크를 빼라는 것이지 정보를 빼라는 것이 아님. 빈 프레임은 깔끔이 아니라 미완성으로 읽힘. 채울 정보가 없으면 잉크가 아니라 프레임을 줄일 것. 또한 반복이 곧 메시지인 경우(예: 변하지 않음을 보여주는 동일 라벨 반복) 잉크 규칙보다 의도가 우선.

## 5. 챕터 1 — 문체 규정

**2단 제목 체계**
- 상단(크게): 주제 라벨 — 기능명·주제 명사 (예: "1. 무사고 전환 (리밸런싱)"). 시나리오·장면 헤더 금지 (예: "건강이 좋아졌을 때" ✕)
- 하단: 헤드메시지 1~2개 단문, 각 35자 안팎. 주장은 여기 삶. 체인 테스트는 이 층에서 수행
- 헤드메시지가 라벨의 반복이면 실패 (정보가 있어야 함)

**개조식·사실체**
- 종결: ~함 / ~됨 / ~임
- 수치가 있으면 문장보다 수치 우선
- 가치판단문은 근거문으로 전환하고 사실과 기대를 분리 (예: "이탈 방지 비용으로 봐야 한다" → "해약 사유 1위 보험료 부담(출처). 요율 인하 시 유지율 개선을 기대함")
- 출처 없는 통계 금지. 미확보 시 "출처 확인 필요" 명기 또는 삭제

**금칙**
- 대구·리듬 슬로건 ("~할수록 ~해지는") ✕
- 은유 ("엔진", "문이 닫히지 않는다") ✕ → 기능·절차 서술로
- 고객 대사·말풍선 인용 ✕ → 상황×결과 표로
- 영문 섹션 라벨 (EXECUTIVE SUMMARY, EXHIBIT, SO WHAT) ✕ → 요약, 도표 N, 시사점. 단 고유명사(이니셔티브명)는 예외
- 과장 수식어 ("신개념", "혁신적") ✕

**문장부호**
- 연결: 콤마 / 부연: 괄호 / 정의·나열 도입: 콜론 / 동급 나열: 가운뎃점(·)
- 대시(—)·하이픈 접두(- ) 사용 금지
- 마이너스 기호 대신 "인하/감소" 서술 (△ 기호는 감소로 오독될 수 있어 변화량 표기에 사용 금지)
- 범위 물결(~), 화살표(→), 더하기(+), ✕/○ 스탬프는 허용

**서사의 지위**: 서사·감성은 삭제가 아니라 강등 — 텍스트 층에서 빼고 본문 비주얼(여정 도표)과 구두 발표로 내림.

## 6. 챕터 2 — 시각 규정 [벤치마크 1개 출처 주의]

- **컨벤션은 반복, 폼은 변주**: 색 의미·스탬프·제목 밴드는 전 장 동일하게, 레이아웃 폼은 연속 2장 이상 동일 금지
- **빈 프레임 금지**: 모든 프레임은 차트·표·조건 줄·각주 중 하나 이상으로 채움 (화해 조항 참조)
- **주장마다 숫자**: 수치가 없으면 가정 수치 + "(예시)" 주석. 예시 가정은 각주에 근거 명기 (예: "* 등급당 5~6% 가정")
- **역할색**: 색은 장식이 아니라 지목. 기본 배정 — 네이비=구조, 파랑=당사·긍정, 빨강=기존의 문제·✕, 회색=기존·중립, 형광노랑=헤드 키워드. 강조는 장당 하나의 유채색 원칙
- **형광 시스템**: 헤드메시지 핵심 구절 형광은 전 장 시스템으로 적용하거나 전무. 단발 사용 금지
- **주석 레이어**: 말풍선 콜아웃·점선 강조 박스는 차트 위 핵심 1곳에만
- **차트 규정**: 축·단위 명기, 범례보다 직접 라벨 우선, 제목이 차트의 결론을 선점, 격자선 최소화

## 7. 챕터 3 — 구멍 유형학 [초안]

체인 확정 후, 제작 전 실행하는 레드팀 검사. 6유형:

1. **프레임 충돌** — 방이 가진 기존 프레임·이전 장표가 내 주장을 기각함. 테스트: "이 방이 본 프레임 중 이 주장을 기각하는 것은?" 보수: 프레임을 부정하지 말고 확장 ("그 프레임이 맞다, 그런데 ~한 예외가 존재하고 그것이 근거다")
2. **암묵 전제** — 체인이 말하지 않은 가정 위에 서 있음. 테스트: "이 링크가 참이려면 무엇이 참이어야 하고, 그건 어디서 증명되나?"
3. **비약** — 헤드 N→N+1 사이 추론 한 칸을 독자가 메워야 함
4. **무방비 절대어** — "유일한·최초·모두" 등 반례 하나에 무너지는 주장. 보수: 한정어 또는 반례 선제 처리
5. **내부 충돌** — 한 장의 주장이 다른 장의 주장·증거를 약화시킴
6. **이해관계 미처리** — 논리는 성립하나 방 안의 누군가가 잃는 것을 다루지 않음

②~⑤는 체인 텍스트만으로 검출 가능. ①·⑥은 오디언스 프라이어(정의서 Q3 보강 3문항)를 입력한 만큼만 검출됨 — 검사 도구는 프라이어를 끌어내는 질문을 강제해야 함.

검출 항목의 처분: (a) 덱에 반영 / (b) 구두 대응으로 결정하고 예상 문답 메모 / (c) 기각(사유 기록). 셋 중 하나로 반드시 처분.

## 8. 폼 스터디 — 관계어 사전 (시드 9종)

메시지 문장 속 관계어가 표현 형태를 결정함. 형태가 안 떠오르면 (a) 메시지에 관계어가 없거나(L2로 회귀) (b) 관계에 대응하는 어휘를 모르는 것.

| 템플릿 | 방아쇠 관계어 |
|---|---|
| 레이어 | 받친다 · 토대 · 전제 · 기반 |
| 허브 | 구동 · 공급 · 중심 · 연결 |
| 전·후 | 바뀐다 · 풀리면 · 활성화 · 전환 |
| 플로우 | 단계 · 순서 · 프로세스 |
| 2×2 | 두 축 · 갈린다 · 포지셔닝 |
| 퍼널 | 좁아진다 · 걸러진다 · 전환율 |
| 막대 비교 | ~보다 크다 · 격차 · 순위 |
| 추세 | 커진다 · 줄어든다 · N년째 |
| 구조화 텍스트 | 원칙 · 기준 · 정의 · 요청 |

- 정량 관계 → 차트(비교 유형이 결정), 정성 관계 → 도해(관계어가 결정), 선언 → 구조화 텍스트
- 글이 정답인 메시지 존재(정의·원칙·요청). 실패는 글이 아니라 문단으로 쓰는 것 — 번호+라벨+한 줄 설명 그리드가 제3의 정당한 형태
- 형태 선택 기준: 메시지에서 어느 단어가 싸움의 핵심인가

## 9. 제작 규칙

- 도구: pptxgenjs (Node), LAYOUT_WIDE 13.33×7.5in, 폰트 맑은 고딕 전 요소 지정
- 루프: 빌드 → 파일 검증 → PDF 렌더 → 육안 QA(전 장) → 수정. 텍스트 충돌·가림·잘림은 렌더에서만 발견됨
- 기존 파일 수정은 python-pptx로 텍스트 교체(서식 보존), 구조 변경 시 리빌드
- 수치 미확보 시 "(예시)" 주석 의무, 각주에 가정 명기
- 실명(동료·협업자)은 어떤 산출물에도 기록하지 않음

## 10. 용어

- **체인**: 전 장의 헤드메시지를 순서대로 이은 것. 체인만 읽어 보고가 성립해야 함 (고스트 덱 테스트)
- **오디언스 프라이어**: 보고받는 방이 이미 가진 프레임·기준·이전 보고
- **폼 스터디**: 한 장의 메시지를 서로 다른 표현 형태 후보로 스케치해 비교·선택하는 단계
- **컨벤션/폼**: 컨벤션=색·스탬프·밴드 등 의미 체계(반복 대상), 폼=레이아웃 구조(변주 대상)
