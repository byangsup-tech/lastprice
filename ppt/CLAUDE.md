# ppt/ — PPT 파이프라인 실행 규칙 (Claude Code용)

이 디렉터리에서 슬라이드·덱 관련 작업을 할 때 아래 규칙을 자동 적용한다.
사람용 정본은 `rulebook/룰북_v0.2.md`, 기계용 정본은 `rules/*.json` — 이 문서는 실행 요약이다.

## 파이프라인 (순서 강제)

정의서 → 헤드라인 체인 → 구멍 검사 → 폼 스터디 → 제작 → 사다리 QA.
"강제"는 단계 건너뛰기 금지이지 수정 금지가 아니다 — 상위 단계를 수정하면 하위 산출물은 재검토 대상.
사용자가 "덱을 만들자"고 하면 먼저 정의서 5문항(룰북 §2)의 답을 확인하거나 질문한다. 체인 확정 전 제작 착수 금지.
평상시 파이프라인 1~4단계는 덱보드 아티팩트에서 진행되고, Claude Code는 주로 제작(5)·QA(6)와 프레임워크 개정을 맡는다.

## 문체 (챕터 1 요약 — 정본: rules/org/<팩>/style.json)

- 장 제목: 기능명·주제 명사를 크게. 시나리오 헤더 금지. 헤드메시지가 라벨 반복이면 실패
- 헤드메시지: 개조식(~함/됨/임) 단문 1~2개, 각 35자 안팎(±5자), 주장 포함. 2문장이면 체인 테스트는 둘 다 읽음
- 금칙: 대구 슬로건, 은유, 고객 대사 말풍선(사실 주석 콜아웃은 허용), 영문 섹션 라벨(고유명사는 exceptions.json 예외), 과장 수식어
- 문장부호 — 허용: 콤마·괄호·콜론·가운뎃점·`~`·`→`·`+`·`✕/○`·각주 `*`·구분자 `|`·원문자. 금지: 대시(—)·하이픈 접두(`- `). 마이너스는 "인하/감소"로 서술, △ 금지
- 출처 없는 통계·타사 사실 주장 금지. 가정 수치는 "(예시)" + 각주 근거

## 시각 (챕터 2 요약 — 정본: rules/org/<팩>/colors.json·visual.json)

- 컨벤션(색 의미·스탬프·밴드·형광)은 전 장 반복, 폼(템플릿)은 연속 2장 동일 금지. "전 장" = 표지·목차·부록 제외 본문 장
- 역할색: 네이비=구조, 파랑=당사·긍정, 빨강=기존 문제·✕(당사 측 강조 금지), 회색=기존·중립, 형광=헤드 키워드(전 장 시스템), 시안/라벤더=기능 구분(전 장 동일 대상). hex는 colors.json이 정본 — 코드·스펙에 직접 쓰지 않음
- L5 잉크 규칙과의 화해: 가정 수치((예시)+각주)는 정보 있는 잉크라 제거 대상 아님. 구조적 프레임은 축소보다 최소 정보로 채움
- 주석 레이어(콜아웃·강조 박스)는 차트당 1곳, 동시 사용 금지. 차트·밴드 제목은 서술 라벨(결론은 헤드메시지 전용)

## 제작 워크플로 (덱 스펙 → pptx)

입력은 항상 deck-spec JSON (`schema/deck-spec.schema.json`). 사용자가 스펙을 붙여넣거나 덱보드에서 내보낸 것을 전달하면:

1. 스펙을 `decks/<덱이름>/deck-spec.json`으로 저장
2. `npm run deck:validate -- decks/<덱이름>/deck-spec.json` — 에러 전건을 표로 보고, 자동 수정 가능 항목은 수정안 제시
3. `npm run deck:build -- decks/<덱이름>/deck-spec.json` — pptx 생성 (스펙의 meta.fileName으로 같은 디렉터리에 출력)
4. `npm run deck:qa -- decks/<덱이름>/<파일>.pptx` — 렌더 QA. soffice가 있으면 슬라이드 PNG 생성 → PNG를 Read로 열어 육안 점검, 없으면 텍스트 추출 대조만 수행되고 "렌더 미수행"으로 보고됨 (그 사실을 사용자에게 명시할 것)
5. 육안 QA 체크리스트 — 장별로 표로 보고:
   - 렌더 결함: 텍스트 충돌·가림·잘림 (렌더 가능 환경에서만)
   - 사다리 L1~L5 (rules/core/ladder.json): L1 존재(체인에서 맡은 저항) → L2 메시지(주장인가) → L3 증거(본문이 증명하는가) → L4 시선(3초) → L5 잉크(화해 조항 적용)
6. 수정 → 2~5 반복. **완성 기준: validate 0건 + 렌더 결함 0건 + 사다리 통과**

pptxgenjs 주의: 색은 `#` 없는 6자리 hex(Theme 경유), `LAYOUT_WIDE`(13.33×7.5in), 전 텍스트 요소 fontFace 지정. 기존 pptx의 텍스트만 고칠 때는 python-pptx run 단위 교체(서식 보존), 구조 변경은 스펙 수정 후 리빌드.

## 프레임워크 개정 워크플로

- 규칙 개정: 룰북 조항과 rules JSON을 **쌍으로** 수정 → `npm run artifact:build` → `git diff ppt/artifact/deckboard.jsx`로 아티팩트 반영 확인 → 골든 재빌드로 회귀 확인 → `rulebook/CHANGELOG.md` 기록. 대응표는 CHANGELOG의 "조항 ↔ rules 대응표"
- 부서 이동(조직 팩 교체): `README.md`의 절차를 따름 — 벤치마크 재추출 → `rules/org/<새팩>/` 4파일 생성 → `rules/active.json` 전환 → 룰북 §5·§6 개정 → 아티팩트 재조립 → 골든 재빌드 회귀 확인
- 아티팩트 수정: `artifact/src/deckboard.template.jsx`만 편집 (deckboard.jsx는 생성물 — 직접 수정 금지) → `npm run artifact:build` → **`npm run artifact:test`(순수 로직 회귀 58건)** → 사용자가 deckboard.jsx 전문을 claude.ai 아티팩트에 붙여넣어 갱신
- 아티팩트에 React 컴포넌트를 추가할 때 **컴포넌트를 다른 컴포넌트 본문 안에서 정의하지 말 것** — 렌더마다 타입 정체성이 바뀌어 입력칸의 포커스·한글 조합 상태가 글자마다 날아간다 (모듈 스코프에 두고 props로 받을 것)
- 아티팩트가 내보내는 하드코딩 문자열(각주 등)도 문체 규정 대상이다 — 금지 기호가 섞이면 덱보드가 자기 엔진 검증에서 떨어지는 스펙을 만든다

## 금지

- 실명(동료·협업자) 기록 금지
- 통계·수치 창작 금지 — AI·도구가 채운 수치는 assumed 플래그 + "(예시)" + 각주 없이는 스펙에 넣지 않음
- 체인 없이 장 단위 제작 착수 금지
- deck-spec·엔진 코드에 색 hex 직접 기입 금지 (colors.json role만)
- `artifact/deckboard.jsx` 직접 수정 금지 (template + artifact:build 경유)
